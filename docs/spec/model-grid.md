# Model grid — v1 (draft)

A role never names a model. It states what kind of thinking it needs, and the
engine picks a model the available agent can run. Models come and go every few
months; roles should not have to change when they do.

## What a role declares

In `role.yaml`:

```yaml
model:
  capability: writing     # coding | reasoning | writing | classification
  tier: light             # light | standard | frontier
  effort: low             # none | low | medium | high | max
```

- **capability** — what the decision is mostly about. Writing a commit message
  is `writing`; designing a module is `reasoning`; changing code is `coding`;
  sorting findings into categories is `classification`.
- **tier** — how strong a model the decision deserves. Tiers are cost bands
  within one provider, not scores: `light` is that provider's cheap, fast
  family, `frontier` its best.
- **effort** — how long the model may think. Each agent maps it to its own
  setting; values a model does not support are clamped to the nearest one.
- **tasks** — a kind of task that needs other thinking than the rest of the
  role, named by `pre` in `in/task-kind`: the documentalist judges a doc on
  `standard`, and condenses one on `frontier` (`tasks: {condense: {tier:
  frontier}}`), because the evaluation showed it cheaper than a `standard` try
  stepped up.

## The grid

`models.grid.yaml` translates those needs into a model and an effort setting per
agent. It is generated by a script, read by a human, and committed:

```yaml
generated: 2026-09-23
sources:                          # cited, as their licences require
  catalog: models.dev api.json (MIT)
  scores: Epoch AI benchmark hub (CC BY 4.0)
  arena: LMArena leaderboard dataset (CC BY 4.0)

grid:
  writing:
    light:    {claude: haiku,  codex: <model>, agy: <model>}
    standard: {claude: sonnet, codex: <model>, agy: <model>}
  coding:
    frontier: {claude: opus,   codex: <model>, agy: <model>}

effort:                           # our level -> the agent's own value
  claude: {none: low, low: low, medium: medium, high: high, max: max}
  codex:  {none: minimal, low: low, medium: medium, high: high, max: xhigh}
  agy:    {none: low, low: low, medium: medium, high: high, max: high}
```

A project can pin or forbid models in `.workline/config.yaml`; a pin always wins
over the grid.

## Refreshing it

`run-role grid refresh` is deterministic and uses no AI:

1. **Which models exist** — models.dev: providers, families, cost, lifecycle
   status, and the effort values each model accepts.
2. **How good they are** — Epoch AI's benchmark hub, one download, many
   benchmarks. Coding: Terminal-Bench, SWE-bench Pro. Reasoning: GPQA,
   FrontierMath. Writing: LMArena text, with style control.
3. **Scores** are turned into percentiles within each benchmark, then averaged
   per capability. A benchmark older than six months weighs less.
4. **Output** is a diff of `models.grid.yaml`. Nothing changes until a human
   accepts it — the same rule as a dependency update.

Model names differ between sources. The table that matches them is kept by hand;
it is the part a script cannot be trusted with.

## Resolving a model at run time

1. The project's pin for this role, if any.
2. The grid cell for the role's capability, tier and agent.
3. The same capability, one tier down.
4. The agent's own alias for that tier, when it has one (`sonnet`, `opus`).
5. The agent's default model.
6. No model at all: the role runs as `--ai none` and its `without-ai` rule applies.

The engine logs which step answered, so a run on a fallback is visible, not silent.
Each call records the tier and effort asked and the exact model that answered,
as the agent reports it (`claude-haiku-4-5-20251001`, not `haiku`): an alias
moves to a newer generation on its own, and a score is only worth something
next to the model that earned it.

Tiers follow the agents' aliases rather than pinned ids, so a new generation
comes in without an update to workline; the engine notices when it does
(`model-changed`, once per machine), and the evaluation measures it. A model is
pinned only when a measurement shows the new one doing worse
([ADR-0004](../adr/0004-follow-model-aliases-and-measure.md)).

*Built so far: the record, the notice, and forcing one model or effort for
every role (`--ai claude:<model>@<effort>`, also in `ai:`), which the
evaluation uses to compare them. Not yet: the grid, pins per role; Claude's
aliases stand for the tiers.*

## Stepping up after failures

A light model is the right default, not a ceiling. When the agent's intentions
are refused, or `post` blocks on what the agent produced, the engine may retry
one tier up:

```yaml
model:
  capability: writing
  tier: light
  effort: low
  promote-after: 2        # refused attempts before one last try a tier up; 0 = never
```

The ladder stops at `frontier`. The number of attempts is capped at
`promote-after` + 1: the last one is the only one a tier up.

## Independent judgement

A reviewer that shares the author's model shares its blind spots. A role can
require a different provider from another role:

```yaml
model:
  capability: reasoning
  tier: standard
  effort: high
  independent-of: developer   # never the provider the developer ran on
```

If no other provider is available, the engine does not quietly fall back to the
same one: the role runs as `--ai none`.

## Known limits

- Benchmarks measure a model inside one harness. The same model scores
  differently under Claude Code and under Codex.
- Arena rankings measure preference in conversation, not work in a repository.
- Subscriptions and API keys do not offer the same models. An agent declares
  which one it uses, and the grid only offers what that billing can reach.
