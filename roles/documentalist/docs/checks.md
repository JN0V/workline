# Documentalist — the checks

What `pre` finds with no AI, and how much each finding weighs. How
cascades are cut and the release held: [cascades](cascades.md). Part of
[the documentalist](../README.md). Gardening is the scheduled run, nightly
or weekly (`schedule`).

## Prepare (`pre`, no AI)

Twelve checks. Six read a doc against the code it describes, below. Six
read the docs alone ([the checks on the docs alone](checks-docs.md)):
budgets, duplicates, links, superseded decisions, docs not read, docs for
their reader. Not built yet: style (vale).

### Suspects

For each doc, the commits since its `checked` commit that touched its
`sources`, named in a `<!-- workline … -->` comment at its top, which no
rendering shows, or in a frontmatter the doc has.

- **No change**: a commit changing only docs' headers, who checked them;
  nor, on a release tool's pull request, one only putting a version number
  in place of another, line for line — the tool's bump, which would hold
  every release — unless the doc quotes the version replaced.
- **A `checked` the branch does not hold** — one of a merge request since
  squashed or rebased — stands for the commit that brought it there, as
  does a `judged` or `judged-in-parts`
  ([ADR-0013](../../../docs/adr/0013-what-was-judged-is-not-asked-again.md)).
  With none, the doc is suspect and read against its sources as they are
  now, never blocking.
- **A shallow clone**: the commit at its edge holds every file as if it
  brought them. When that is the only one bringing the name, the clone
  lacks the commit, and `shallow-clone` says so — the doc neither suspect
  nor passed.
- **At a push, only the docs its commits touched**: one of their sources,
  or the doc itself. The others are read on the merge request and when
  gardening
  ([ADR-0050](../../../docs/adr/0050-each-act-has-its-moment-and-a-wait-budget.md)).
- **The chain is followed**: a suspect technical section makes the product
  docs depending on it suspect too.

### Identifiers gone

A name in a code span that was in the code when the doc was last edited,
and is gone now — the method of DOCER, a research tool
([research](../../../docs/research/documentalist.md)).

- A name never in the code is not reported: it may be a product term.
- Given the commits of a push or a merge request, only the names they
  removed are searched for: searching the code at each doc's last edit
  took minutes on a large repository; the rest is for gardening.

### Derived blocks

The text between `<!-- workline:derive name -->` and
`<!-- workline:end -->` is the output of the command the project names in
`settings.derive`.

- **On the default branch only** — when gardening and on `init` — a stale
  block is regenerated by the role itself, with no agent (`derived-stale`,
  applied as a patch).
- **On a push, a merge request or a release** it is reported behind
  (`derived-behind`) and left as it is, so two branches adding to one count
  do not conflict on its line
  ([ADR-0027](../../../docs/adr/0027-derived-blocks-are-regenerated-on-the-default-branch.md)).
- Commands live in the config, which only people change, never in a doc;
  they run wherever the line runs, CI included.

### Code no doc describes

A file matching the project's `documented` globs that no doc names in its
sources, by folder (`undocumented`): those the commits add, given a range;
all of them otherwise. A source that no longer exists is `source-gone`, and
what removed it reaches the doc as any change does.

### Freshness

On `schedule`, a doc last confirmed more than `freshness.stale-after-days`
ago (180) is `stale`.

- It is dated by the commit its `checked` names, not by its last edit,
  since a doc nobody reads again drifts from a world that changed around it
  (Google's freshness dates). Docs already suspect or pending are left out.
- When gardening finds no suspect doc to judge, the agent reads the stale
  ones again against their sources, when these fit a task and can be read.

### Line counts off

`count-off`
([ADR-0014](../../../docs/adr/0014-checked-is-earned-by-what-was-read.md),
step 2): a count of lines next to a file the doc names among its sources
(matched by path suffix, one file only), off from the file as it is now.

- **Where**: in prose ("`EventBus.h` is currently ~283 lines"; "`OTA.cpp`
  line count (607)", "line count: 607"; "a 216-line `JsonStreamWriter.h`",
  the file right after the count), a fenced listing ("Clock.h (524
  lines)") or a table whose column is headed `Lines`.
- **A table's row of totals** (`Total`) is a count too, the sum of its
  rows, when each row counts one source file.
- **Thousands** apart with a comma or a space ("1,008", "1 200"), a
  no-break or narrow no-break one too, are read whole.
- **Right** within one line, or within a tenth when it says it is about
  (`~`, about, approximately).
- **Not a count**: a number beside a limit word (`<`, under, over, limit,
  max, target, …); "an 800-line limit", with no file right after it;
  anything in a doc with `sources: []`, a history doc (a changelog or
  release notes, however named or foldered, a decision record, a tried or
  research record, or a doc of the project's `history` globs: role.yaml)
  or a derived block.
- **Reported** with the file, the count stated and the real one. While one
  stands, `checked` cannot move ([the judge](judge.md#moving-checked)).
- **No agent counts**, and only lines are counted: tests, fields and other
  counts go through a project's `derive`, never guessed.

Why (step 4): on DomoticsCore, a C++ project the role runs on in CI
([tried for real](tried.md)), "`OTA.cpp` line count (607)" went unreported,
and its right fix was refused for want of a claim; an OTA table's total,
unreported, was withdrawn by the agent for want of a claim.

## Levels

Findings are reported rather than blocking while they are new (warn before
block, the [role contract](../../../docs/spec/role-contract.md)); a project
turns one off with `enforce`.

- **Reported; the run passes**: `suspect`, `pending`, `unchecked`,
  budgets, `duplicate`, `dead-link`, `external-link-broken`,
  `identifier-gone`, `count-off`, `value-left` (after a fix, the judge),
  `cites-superseded`, `stale`, `links-not-checked`, `nothing-tracked`,
  `no-sources` and `sources-by-name` (on `init`), `undocumented`,
  `source-gone`, `docs-not-read`, `gardening-paused`, the reader checks,
  `too-large-to-condense`, `too-large-to-split`, `too-large-to-read`,
  `reader-claim-dropped` and `reader-patch-withheld` (gardening); for a
  doc judged in parts, `sources-too-wide`, `uncovered`, `claims-dropped`;
  on a draft, `ai-waits-for-ready`.
- **Reported, and the block regenerated**: `derived-stale` (gardening,
  `init`).
- **Reported, left as it is**: `derive-unclosed`, a derive marker with no end before the next block's ([#302](https://github.com/JN0V/workline/issues/302)).
- **Reported; the block left for gardening**: `derived-behind` (push,
  merge request, release).
- **Blocks**:
  - `due`: on `release`, a doc due then and not brought up to date;
  - `unknown`: a source that could not be read;
  - `setting-missing`: a budget or threshold not set, so a check did not
    run;
  - `derive-unknown` and `derive-failed`: a derived block that could not
    be regenerated;
  - on `release`, a `suspect` doc ([cascades](cascades.md#at-the-release));
  - `shallow-clone`, unless only docs the commits in range did not touch
    lack their `checked` (then reported).
- **`blocked-external`**: a source repository that cannot be reached.
